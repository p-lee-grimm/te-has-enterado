# Qué Pasa — ежедневный дайджест испанской повестки на русском

Раз в сутки собирает 4–7 сюжетов, которые обсуждают в Испании, пересказывает их
по-русски своими словами, добавляет контекст для человека без испанского
бэкграунда и показывает, как одно и то же событие подают издания разных
политических полюсов.

Публикуется в Telegram. Запускается по cron в GitHub Actions, участия человека
в штатном режиме не требует.

**Главный принцип: при любой аварии выпуск не выходит, а не чинится ночью.**
Ворота качества (`gate`) снимают выпуск с публикации и присылают владельцу
причину в личку. Пропущенный выпуск дешевле плохого.

## Быстрый старт

```bash
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

Заполнить `.env` (шаблон — `.env.example`):

```bash
cp .env.example .env
```

| Переменная | Зачем | Обязательна |
|---|---|---|
| `DATABASE_URL` | Postgres с расширением `pgvector` (Supabase) | да |
| `CONTACT_EMAIL` | попадает в User-Agent — требование §5.6 | да |
| `ANTHROPIC_API_KEY` | пересказ, если `summarize.provider: anthropic` | зависит |
| `CLAUDE_CODE_OAUTH_TOKEN` | пересказ в CI, если `summarize.provider: claude_cli` | зависит |
| `VOYAGE_API_KEY` | эмбеддинги | для `embed` |
| `TELEGRAM_BOT_TOKEN` | публикация | для `publish` |
| `TELEGRAM_OWNER_CHAT_ID` | запасной адрес, если нет `REVIEW_CHAT_ID` | нет |
| `REVIEW_CHAT_ID` | чат служебных сообщений: ревью, аварии, карточки, сводки | для `publish` |
| `TELEGRAM_CHANNEL_ID` | канал | для `publish` |

Схема и первый прогон:

```bash
python run.py --migrate
python run.py --all
```

`--all` без флагов работает в режиме `--dry-run`: ничего не пишет в базу и
ничего не публикует, только печатает. Чтобы прогон был настоящим, нужен
явный `--commit`.

Локальная база для разработки, если нет Supabase под рукой:

```bash
docker run -d --name quepasa-pg -e POSTGRES_PASSWORD=quepasa -e POSTGRES_DB=quepasa -p 55432:5432 pgvector/pgvector:pg16
```

## Консоль оператора

```bash
python serve.py                 # http://127.0.0.1:8765
```

Локальная страница для того, что нельзя сделать автоматом, — посмотреть глазами
и разметить руками. Слушает только `127.0.0.1`, наружу не смотрит, в проде не
крутится. Это инструмент владельца, а не веб-фронт продукта (§0 non-goals).

| Вкладка | Зачем |
|---|---|
| Обзор | сколько статей и сюжетов, последние прогоны, стоимость LLM |
| Разметка пар | две кнопки на пару: «один сюжет» / «разные» |
| Порог | сетка порогов и рекомендация по твоей разметке |
| Сюжеты | что сейчас в работе, подсвечены проходящие «≥3 источника»; отсюда готовится пост |
| Посты | опубликованное и сколько изданий ждёт добавления в пост |
| Источники | здоровье фидов, доля статей с полным текстом |

Кнопки «запустить прогон» там нет специально: запуск — дело cron, а консоль
нужна, чтобы смотреть и размечать.

## Публикация: пост на сюжет

Канал живёт не дайджестами, а отдельными постами: один сюжет — один пост.
Издания пишут об одном событии не одновременно, поэтому пост **дополняется**:
подтянулось ещё одно издание — бот правит сообщение, а не постит второе.

Пост состоит из трёх частей:

```
**Нейтральный заголовок по-русски**       <- пишет человек, markdown
текст, если нужен

⬅️ elDiario.es · infoLibre                 <- собирается заново при каждой правке
◀️ El País · 20minutos
➡️ ABC · La Razón

#экономика                                 <- хэштег категории
```

Шапка и блок ссылок разделены намеренно: при дополнении пересобирается только
блок ссылок, ручной текст не трогается.

| Значок | Позиция |
|---|---|
| ⏪ | крайне левые |
| ⬅️ | левые |
| ◀️ | левоцентристские |
| ↔️ | центристские |
| ▶️ | правоцентристские |
| ➡️ | правые |
| ⏩ | крайне правые |
| 🏛 | официальные источники (BOE, Moncloa) — не позиция, а первоисточник |

Расшифровку стоит закрепить в канале: сами по себе стрелки читателю ни о чём
не говорят. Готовый текст — `python -c "import sys;sys.path.insert(0,'src');
from quepasa.posts import legend_md;print(legend_md())"`.

### Правило автопостинга

Какой сюжет достоин поста — задаётся в `config/settings.yaml` → `autopost`.
Посмотреть, что правило отберёт, ничего не публикуя:

```bash
python run.py --autopost
```

Условия объединяются по ИЛИ — достаточно любого:

| условие | сюжетов за 47 ч |
|---|---|
| есть левое **и** правое | 22 |
| (левое **или** правое) **и** центристское | 27 |
| ≥3 источников | 20 |
| **вместе, без двойного счёта** | **42 → ~21 в сутки** |

**Строгое сравнение полюсов брать нельзя**: если считать «левым» только
`left`/`far-left`, а «правым» только `right`/`far-right`, правило даёт один
сюжет за двое суток. Причина не в новостях, а в составе источников — изданий
с меткой `left` всего два, `far-left`/`far-right` не проставлены никому.
Поэтому по умолчанию `lean_groups_broad: true`: левоцентристские и
правоцентристские считаются сторонами.

### Второй ярус: дайджест

Всё, что не прошло в отдельный пост, собирается в один пост по категориям:

```bash
python run.py --digest-post          # сухой прогон
python run.py --digest-post --commit
```

Категория, в которой меньше `min_items_per_category` пунктов, сливается
в блок «Прочее» — за сутки категории мелкие, и отдельный заголовок ради
одной строки только мешает.

**Важно про порог `digest.min_sources`.** По умолчанию 2. Если поставить 1,
в дайджест хлынут одиночные материалы — а это ~300 штук в сутки уровня
«коктейли в Аликанте» и «Louis Vuitton одевает Реал». Один источник — это не
общая повестка (§3.7), и в дайджесте ему делать нечего. При пороге 2 в
дайджест попадает ~4 сюжета в сутки.

Статистика пересчитывается на своих данных:

```bash
python scripts/stats.py
```

### Как опубликовать

1. `python serve.py` → вкладка **Сюжеты** → «пост →» у нужного сюжета.
2. Написать заголовок по-русски, выбрать категорию. Справа — превью
   ровно в том виде, в каком пост уйдёт в Telegram.
3. «Опубликовать в канал».
4. Когда подтянутся новые издания — «Обновить пост» на той же странице
   или разом по всем: `python run.py --sync-posts --commit`.

Вкладка **Посты** показывает всё опубликованное и колонку «новых» — сколько
изданий появилось после публикации и ждёт правки.

## Служебный чат

Всё, что бот пишет владельцу, идёт в один чат — `REVIEW_CHAT_ID`
(сейчас «Te has enterado Soporte»). Черновики на ревью, непрошедшие ворота,
карточки сущностей, недельная сводка. Одно место просматривают, три
игнорируют, поэтому разводить по разным чатам не стоит.

Служебные сообщения всегда беззвучные: это рабочая переписка, а не новость.

**Вебхук.** Кнопки ревью работают через `getUpdates`, а Telegram запрещает
его, пока у бота стоит вебхук. Если снова повесишь на этого бота вебхук
(n8n, например) — кнопки перестанут работать молча. Проверить:

```bash
python -c "import sys;sys.path.insert(0,'src');from quepasa.config import load_dotenv;load_dotenv();from quepasa.telegram import _call;print(_call('getWebhookInfo',{}))"
```

## Запуск на сервере

```bash
git clone https://github.com/p-lee-grimm/te-has-enterado.git quepasa && cd quepasa
python3.12 -m venv .venv && ./.venv/bin/pip install -r requirements.txt
cp .env.example .env   # заполнить
./.venv/bin/python run.py --migrate
./.venv/bin/python manage.py entity seed
```

База — контейнер с pgvector на свободном порту:

```bash
docker run -d --name quepasa-pg --restart unless-stopped \
  -e POSTGRES_PASSWORD=quepasa -e POSTGRES_DB=quepasa \
  -p 127.0.0.1:55433:5432 -v quepasa_pgdata:/var/lib/postgresql/data \
  pgvector/pgvector:pg16
```

Расписание — три скрипта в `bin/`:

```
7 * * * *        bin/cycle.sh     сбор, эмбеддинги, кластеризация, уборка
*/30 * * * *     bin/publish.sh   нажатия, автопостинг, дополнение, сверка фактов
25,30 19,20 * *  bin/evening.sh   вечерний пост (час сверяется по Мадриду в коде)
```

Скрипты сами задают `PATH` (cron даёт минимальный, и `claude` из `~/.local/bin`
в нём не виден) и берут `flock`: сбор идёт три минуты, и второй прогон поверх
первого подрался бы за фиды и за квоту.

Проверить, живо ли всё:

```bash
./.venv/bin/python run.py --status
```

## Как это устроено

```
fetch → normalize → dedupe → embed → cluster → rank → select → summarize → render → gate → publish
```

Каждая стадия — отдельный модуль в `src/quepasa/stages/`, запускается
самостоятельно. Недостающий вход стадия добирает из базы, поэтому
`--stage render` работает и без предшествующего `--stage ingest`.

```bash
python run.py --stage ingest --commit     # собрать статьи
python run.py --stage cluster --commit    # разложить по сюжетам
python run.py --stage render              # посмотреть, как выглядит пост
```

| Стадия | Что делает |
|---|---|
| `ingest` | тянет фиды, нормализует записи, достаёт полный текст, дедуплицирует |
| `embed` | считает эмбеддинги (один раз на статью, никогда не пересчитывает) |
| `cluster` | инкрементально раскладывает статьи по сюжетам |
| `rank` | считает скор сюжета |
| `select` | отбирает информационный минимум |
| `summarize` | один вызов LLM на сюжет, строгий JSON на выходе |
| `render` | верстает пост в HTML-разметке Telegram |
| `gate` | ворота качества: решает, публиковать ли вообще |
| `publish` | шлёт владельцу на ревью или сразу в канал |

Коды возврата `run.py`: `0` — успех, `1` — упало, `2` — ворота не пропустили
выпуск (штатный исход), `3` — сейчас не время запуска (`--check-schedule`).

## Частые задачи

### Добавить источник

Никогда не вписывай URL фида руками, не проверив. Добавь кандидата
в `config/sources.candidates.yaml` (можно несколько вариантов URL на издание):

```yaml
  - id: nuevo
    name: Nuevo Diario
    type: press          # press | agency | official
    lean: center-left    # проставляется вручную, автоклассификации нет
    urls:
      - "https://ejemplo.es/rss/"
```

Затем:

```bash
python scripts/validate_feeds.py            # таблица: что живо, что нет
python scripts/validate_feeds.py --write    # прошедшие проверку -> sources.yaml
```

Если у издания не нашлось рабочего RSS, оно попадёт в `sources.yaml`
со статусом `disabled`. HTML в v0 не парсим — так и оставляем.

Не знаешь адрес фида — спроси сайт:

```bash
python scripts/validate_feeds.py --discover https://ejemplo.es/
```

Проверка ловит и «живые мертвецы»: фид отдаёт 200 и валидный XML, но последняя
запись двухлетней давности. Так отсеялись RTVE и старый портальный фид ABC.

### Проверить, не сломались ли источники

```bash
python scripts/validate_feeds.py --check-current
```

### Поменять порог кластеризации

Порог `0.82` в спецификации — догадка, и он зависит от модели эмбеддингов.
Размечать пары в терминале невыносимо, поэтому для этого есть консоль:

```bash
python serve.py       # http://127.0.0.1:8765 -> вкладка «Разметка пар»
```

Две кнопки на пару: «один сюжет» или «разные». Размеченное копится в таблице
`pair_labels` и сразу превращается в рекомендованный порог — на вкладке
«Порог». Консоль честно скажет, если классы пересекаются: бывает, что пары
«разные» имеют близость выше, чем некоторые «одинаковые», и тогда идеального
порога просто нет.

Тот же отчёт в терминале, если так привычнее:

```bash
python scripts/tune_threshold.py --from 0.70 --to 0.90 --step 0.02 --pairs 20
```

Порог правится вручную в `config/settings.yaml` → `cluster.sim_threshold`.
Автоматически он не применяется никогда: решение за владельцем.

Калибровать имеет смысл, только когда в базе накопился корпус за несколько дней.
На пустой базе кластеризацию отладить нельзя. И помни: разметка привязана
к модели эмбеддингов — сменишь провайдера, размечать придётся заново.

### Исключить издание, которое попросило его не использовать

`config/settings.yaml`:

```yaml
blocked_sources: [okdiario]
```

Отключает источник немедленно, правки `sources.yaml` не требуются (§5.7).

### Перейти от ревью к автопубликации

Первые 2–3 недели `publish.review_mode: true`: выпуск приходит владельцу
в личку с кнопками «Опубликовать» / «Пропустить», без нажатия за 3 часа не
публикуется. Когда доверие набрано — `review_mode: false`.

### Выпуск не вышел, что делать

Сначала посмотреть, что написал бот в личку — там причина. Дальше:

```sql
SELECT started_at, status, stage_stats->'gate' FROM runs ORDER BY id DESC LIMIT 5;
```

Типичные причины:

| Причина | Что значит |
|---|---|
| `число пунктов` | меньше 4 сюжетов набрали ≥3 источника — тихий новостной день или слишком высокий порог кластеризации |
| `фиды` | отработало меньше 70% источников — проверь `validate_feeds.py --check-current` |
| `объём` | статей сильно меньше медианы — вероятно, тихо сломался парсинг |
| `цитирование` | в пересказе нашёлся дословный кусок статьи — правь `prompts/summarize.md` |
| `ссылки` | в посте битая ссылка |
| `поля` | модель вернула пустое или обрезанное поле |

**Чинить на следующий день, а не ночью.** Один пропущенный выпуск ничего не стоит.

## Что настраивается

Все пороги, веса и лимиты — в `config/settings.yaml`. В коде чисел нет.
Промпты — в `prompts/*.md`, тоже не в коде.

Самое востребованное:

| Ключ | Смысл |
|---|---|
| `cluster.sim_threshold` | когда две статьи считаются одним сюжетом |
| `select.min_unique_sources` | сколько изданий делают сюжет общей повесткой (3) |
| `select.max_items` / `min_items` | размер выпуска (7 / 4) |
| `rank.weights` | что важнее при отборе |
| `publish.review_mode` | ревью владельцем или автопубликация |
| `embed.provider` | `voyage`, `openai`, `cohere` или `local` |

### Откуда берётся текст: ключ или подписка

`summarize.provider` — два варианта:

| | `claude_cli` (по умолчанию) | `anthropic` |
|---|---|---|
| Как ходит | `claude -p` на твоей подписке | HTTP по `ANTHROPIC_API_KEY` |
| Отдельный ключ | не нужен | нужен |
| Локально | работает из терминала, где ты уже авторизован | работает |
| В GitHub Actions | нужен `CLAUDE_CODE_OAUTH_TOKEN` из `claude setup-token` | работает как есть |

Локально удобнее `claude_cli`: консоль запускается из твоего терминала,
и кнопка «Сгенерировать» ничего дополнительно не стоит.

Для ежедневного cron надёжнее `anthropic`: это обычный серверный вызов,
он не зависит от состояния авторизации Claude Code и не привязан к тому,
что подписка предназначена в первую очередь для интерактивной работы.
Если всё же хочешь `claude_cli` в Actions — сделай токен:

```bash
claude setup-token
```

и положи его в секрет `CLAUDE_CODE_OAUTH_TOKEN`. Workflow сам поставит CLI,
когда этот секрет задан.

### Про эмбеддинги и лимиты Voyage

Модель — `voyage-4`: у неё 200 млн токенов бесплатной квоты, тогда как у
`voyage-3.5` она уже израсходована. При потоке ~7 млн токенов в месяц квоты
хватит года на два.

Лимиты у Voyage двойные — и по запросам, и по токенам в минуту, — и упереться
можно в любой. Без привязанной карты это **3 запроса и 10 000 токенов в минуту**:
на таком тарифе первичный расчёт 945 статей занимает ~40 минут, и это потолок
самого лимита, а не кода. С картой — 2000 и 3 млн, те же 945 статей считаются
за полминуты.

Значения лежат в `embed.requests_per_minute` и `embed.tokens_per_minute`.
Если вернёшься на бесплатный тариф — верни туда 3 и 10000, иначе стадия будет
ловить 429. Пачки нарезаются по `max_tokens_per_request`, а не по числу статей:
лимит считается в токенах.

### Про `embed.provider: local`

Офлайн-заглушка для разработки без ключей: мешок слов, разложенный хэшем.
Ловит лексическое сходство, но не перефраз. Годится, чтобы прогнать пайплайн
и посмотреть на механику, **не годится для калибровки порога и для прода** —
косинус там живёт в другом диапазоне, чем у настоящей мультиязычной модели.
Для боевого режима поставь `voyage` и ключ.

## Юридические требования

Реализованы кодом, а не обещаниями. Испания — юрисдикция со смежным правом
издателей прессы (ст. 129 bis TRLPI) и с историей исков к агрегаторам.

| Требование | Где обеспечивается |
|---|---|
| Никаких цитат из статей | `prompts/summarize.md` + механическая проверка в `gate` (окно в 10 слов) |
| Ссылки наружу у каждого пункта | `render.pick_links` + проверка в `gate`; пункт без ссылки не публикуется |
| Пересказ ≤ 4 предложений | правило в промпте + проверка в `gate` |
| Полный текст ≤ 72 часов | `articles.body_expires_at`, затирается `run.py --purge-bodies` |
| Уважение `robots.txt` | `net.RobotsCache`, проверка перед загрузкой текста |
| Честный User-Agent с контактом | `http.user_agent`, подставляется `CONTACT_EMAIL` |
| Немедленное отключение по просьбе издания | `blocked_sources` |

Трафик уходит источникам: продукт даёт 2–3 ссылки на издания разных полюсов
в каждом пункте и не удерживает читателя у себя.

## Тесты

```bash
python -m pytest tests/ -q
```

Покрыты нормализация URL, дедуп, схема JSON от модели, логика ворот
(включая вёрстку и правило повтора) и рекомендация порога по разметке. Кластеризация тестами не покрывается
осознанно — она калибруется глазами через `tune_threshold.py`.

---

## Расписание

`19:30` по Мадриду. GitHub Actions умеет только UTC, а Испания переходит на
летнее время, поэтому cron срабатывает и в `17:30`, и в `18:30` UTC, а лишний
запуск отсекает `run.py --check-schedule` по таймзоне `Europe/Madrid`.
Хардкодить UTC-час нельзя — полгода выпуск выходил бы на час не вовремя.

Секреты — в Settings → Secrets and variables → Actions. В репозитории ключей
нет и быть не должно.

## Структура

```
run.py                     единственная точка входа
serve.py                   локальная консоль оператора (127.0.0.1)
config/
  settings.yaml            все пороги, веса и лимиты
  sources.yaml             проверенные фиды (генерируется validate_feeds.py)
  sources.candidates.yaml  кандидаты на проверку
prompts/summarize.md       промпт пересказа с few-shot примерами
migrations/*.sql           схема, идемпотентная
scripts/
  validate_feeds.py        проверка и поиск фидов
  tune_threshold.py        калибровка порога в терминале
  weekly_report.py         недельная сводка владельцу
src/quepasa/
  config.py  db.py  net.py  embed.py  llm.py  telegram.py
  textutil.py  schedule.py  pipeline.py  calibrate.py
  stages/    ingest embed_stage cluster rank select summarize render gate publish
```
